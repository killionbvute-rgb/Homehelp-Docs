# Domain Design Reviews

## Purpose

Domain Design Reviews capture architectural reasoning before implementation begins.

They bridge Sprint Blueprints and Architecture Decision Records (ADRs).

A Domain Design Review evaluates proposed domain concepts, aggregate boundaries, responsibilities, and architectural trade-offs before implementation.

---

## Lifecycle

Sprint Blueprint

↓

Domain Design Review

↓

Architecture Decision Record (if required)

↓

Implementation

↓

Architecture Alignment Review

↓

Retrospective

---

## Objectives

Each review should:

- Evaluate proposed domain concepts
- Validate aggregate boundaries
- Identify domain events
- Define responsibilities
- Assess architectural alternatives
- Record accepted and rejected options
- Produce recommendations for implementation

---

## Scope

Domain Design Reviews are working documents.

Unlike ADRs, they capture analysis rather than final architectural decisions.
